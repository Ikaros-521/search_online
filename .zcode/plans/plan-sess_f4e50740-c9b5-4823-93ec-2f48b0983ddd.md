## 实现计划：多引擎支持 + 配置文件可配置

### 背景（已实测）
- 必应：7/7 可用（base64解码URL方式）
- 百度：频繁触发验证码（IP级反爬，已检测）
- 搜狗：可用！跳转链接 `/link?url=` 页面含 `window.location.replace("真实URL")`，可用正则提取
- 360搜索：部分可用（直接真实URL可用；`/link?m=` 加密跳转无法解析，跳过）

### 一、新建 `config.json`（项目根目录）

```json
{
  "engine": "baidu",
  "engine_id": 1,
  "engine_priority": ["baidu", "sogou", "bing", "so"],
  "count": 3,
  "proxies": {"http": "", "https": ""},
  "request": {
    "timeout": 30,
    "max_retries": 3,
    "retry_backoff": 1,
    "min_content_length": 200,
    "max_content_length": 8000
  }
}
```

### 二、main.py 改动

1. **`__init__` 支持配置注入**：`SearchEngine(config: Optional[dict] = None)`，从配置读取 timeout/retries/proxies/阈值
2. **新增引擎**：
   - `_sogou_search` + `_parse_sogou_results`：解析 `div.vrwrap`，跳转链接用正则提取 `window.location.replace` 中的真实URL
   - `_so_search` + `_parse_so_results`：解析 `li.res-list`，直接https链接可用，`/link?m=` 跳过（加密无法解）
3. **自动降级**：新增 `search_with_fallback(query)` 方法：
   - 按 `engine_priority` 顺序尝试各引擎
   - 捕获 `SearchEngineBlockedError`（验证码）或空结果 -> 记录日志 -> 降级下一个引擎
   - 全部失败抛最后的异常
4. **`get_summaries` 使用降级逻辑**；`main()` 改为读 config.json
